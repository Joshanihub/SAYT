## Purpose and evidence boundary

This inventory records the public capability areas to investigate for SAYT, then tracks SAYT's own implementation and evidence. It is not a claim that SAYT has parity, and the competitor products' feature pages are not independent measurements of quality. We use their official product pages and manuals as a discovery baseline, then define SAYT-native behavior and tests. Reference products, feature tiers, hardware requirements, licensing and provider terms can change; review the linked official material before adopting a dependency or promising compatibility.

The source review was performed on 2026-11-26. Core official sources: [Serato DJ Pro](https://serato.com/dj/pro), the [Serato DJ Pro manual index](https://support.serato.com/hc/en-us/categories/202698038-Serato-DJ-Pro-manual), [Serato keyboard shortcuts](https://support.serato.com/hc/en-us/articles/233087008-Keyboard-Shortcuts), [Serato MIDI mapping](https://support.serato.com/hc/en-us/articles/209377487-MIDI-mapping-with-Serato-DJ-Pro), and [Serato beatgrids](https://support.serato.com/hc/en-us/articles/202856014-Beatgrids-in-Serato-DJ-Pro); [VirtualDJ feature inventory](https://virtualdj.com/products/virtualdj/features.html), the [VirtualDJ manual index](https://virtualdj.com/manuals/virtualdj.html), [VirtualDJ controller mapping](https://virtualdj.com/manuals/virtualdj/settings/controllers.html), [VirtualDJ deck controls](https://virtualdj.com/manuals/virtualdj/interface/decks/deckbasics.html), and [VirtualDJ audio setup](https://virtualdj.com/manuals/virtualdj/settings/audiosetup.html).

Statuses mean: **NOT STARTED**, **IN DESIGN**, **IN PROGRESS**, **IMPLEMENTED**, **AUTOMATED TESTED**, **RUNTIME VERIFIED**, **OWNER VERIFIED**, **BLOCKED**. Use the highest state actually supported by evidence for each row; code alone does not mean runtime verified. “Owner verified” identifies owner-run physical use and is not independent reproduction.

## Integration rules

- Work remains on `feat/dj-command-system`, created from the pushed M1 head `ee137e288b324a50e6f9b1574c4aee9d4eee1c09`; it includes the ongoing M1 fixes and is isolated in `C:\Dev\SAYT-dj-feature-expansion`. No agent workstream is used.
- The feature track is sequenced, not an excuse to stop M1. M1 audio and failure-path acceptance stays visible in [`FEATURE_ACCEPTANCE_MATRIX.md`](FEATURE_ACCEPTANCE_MATRIX.md).
- The first vertical slice is the command registry and configurable keyboard mapping for actions SAYT already implements. Unsupported cue, loop, sync, effects, sampler, library-search and recording commands stay absent until their real subsystems exist.
- No vendor interface, skin, shortcut map, protected artwork, controller mapping file, provider private API, DRM bypass or sample library is copied into SAYT.
